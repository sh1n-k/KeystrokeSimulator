# Manual E2E Test Plan

자동 테스트로 대체할 수 없는 실제 화면 캡처, OS 권한, 키 입력 hook과 GUI 흐름만 수동 검증합니다. 변경된 영역의 시나리오만 실행하고 결과를 `PASS / FAIL / N/A`로 기록합니다.

Windows system/hotkey 동작을 변경했다면 Windows 실환경 검증은 필수입니다.

## 준비

- macOS 또는 Windows 실사용 환경
- `uv sync` 후 `uv run -m app` 실행 가능
- macOS의 화면 기록 및 손쉬운 사용 권한 허용
- `Quick` 프로필과 삭제 가능한 테스트 프로필 준비
- 색상 변화를 직접 통제할 수 있는 화면 영역 준비

## 앱과 프로필

- 적용 변경: 프로필 경로·저장, 작업 공간 편집·복사, 캡처 HUD
- 대상 OS: macOS 또는 Windows

1. 앱을 실행해 실행 창의 대상·실행·수정키 콤보, ⚙ 메뉴(작업 공간·빠른 이벤트·수정키 세트·설정·로그 삭제), 시작 버튼을 확인한다. Esc를 눌러도 앱이 꺼지지 않는지 확인한다.
2. "편집…"으로 작업 공간을 열고, 사이드바에서 프로필을 복사한 뒤 복사본의 이름을 바꾸고 삭제한다. Quick은 이름 변경·삭제가 없어야 한다. 실행 창 콤보가 바로 갱신되는지 확인한다.
3. 작업 공간에서 규칙과 신호를 추가·수정하고(이름·키·그룹·조건·고급), 창과 앱을 다시 열어 JSON 저장 결과가 유지되는지 확인한다. 기존 이벤트의 "캡처…"는 HUD에 기존 캡처본과 대상 표시를 보여야 하고, 취소하면 화면이 그대로여야 한다.
4. 빠른 이벤트(연속 모드 HUD)로 두 세션에 걸쳐 저장한다. 기존 Quick 이벤트와 키가 남고 이름이 이어지는지(예: 3, 4) 확인한다. 대상을 고른 뒤 게임 화면이 바뀐 다음 CTRL로 적용해도 고른 캡처본이 저장돼야 한다.
5. 캡처 HUD가 게임 위에 항상 보이는지, ALT로 캡처 박스를 HUD 쪽으로 옮기면 HUD가 반대편 모서리로 비키는지, 캡처 영역 테두리가 박스 바깥에 그려지고 캡처본에 찍히지 않는지 macOS와 Windows에서 각각 확인한다. HUD 이름칸에 입력 중일 때 CTRL은 무시돼야 한다. 기존 캡처가 있는 이벤트에서 ALT로 옮긴 뒤 떼도 미리보기가 새 위치를 계속 보여 주고, CTRL로 고정하기 전에는 적용이 거부돼야 한다.

기대 결과: 창이 예외 없이 열리고 프로필 선택, 자동 저장, 복사·삭제가 일관되게 동작한다.

## 조건, 그룹과 그래프

- 적용 변경: 이벤트 스키마, 조건·그룹·그래프, 목록 순서, 저장 검증
- 대상 OS: macOS 또는 Windows

1. 신호를 만든다(＋ 신호 → HUD에서 캡처·적용).
2. 화면 없이 조건만 있는 규칙을 만들고, 조건이 맞을 때만 키가 나가는지 확인한다.
3. 같은 그룹에 규칙 두 개를 두고 드래그로 순서를 바꾼 뒤, 위쪽 규칙만 실행되는지 확인한다. 이름순 정렬과 ⌘Z 되돌리기를 확인한다. 상세 패널에서 화면을 지우거나 다시 캡처한 뒤 ⌘Z로 예전 캡처본이 돌아오는지도 확인한다.
4. 그래프 탭에서 조건 방향과 그룹 관계를 확인한다.
5. 중복 이름은 거부되고, 순환이 생기는 조건 후보는 비활성과 경로로 보이는지 확인한다. 키 없는 규칙에 "키 없음" 배지가 붙고 실행 창 상태가 해결 버튼을 보이는지 확인한다.

기대 결과: 설정과 그래프가 일치하고 잘못된 이벤트 구성이 저장되지 않는다.

## 실제 실행

- 적용 변경: processor, 단축키 묶음(runtime toggle), 캡처, OS listener·권한
- 대상 OS: 변경 대상 OS. Windows system/hotkey 변경은 Windows 필수

1. 유효한 대상과 실행 항목(프로필 또는 실행 세트)을 고르고 시작/중지를 두 번 반복한다.
2. 통제 가능한 픽셀 또는 영역 변화로 이벤트를 한 번 발생시킨다.
3. 키 입력 횟수, 그룹 순서와 단축키 묶음 동작을 확인한다.
4. 실행 중 UI가 응답하며 중지 후 입력과 캡처가 중단되는지 확인한다.
5. 실행 중 작업 공간을 열어 편집한다. "다음 시작부터 반영" 안내가 보이고, 프로필 이름 변경·삭제가 막히며, 다시 시작하면 편집이 반영되는지 확인한다. 빠른 캡처 HUD를 연 채 시작하면 HUD가 닫혀야 한다.

기대 결과: 중복 실행이나 무응답 없이 매칭 이벤트만 실행되고 중지가 즉시 반영된다.

## 설정과 복원

- 적용 변경: 설정 저장·소비, 언어, 수정키, 창 상태 복원
- 대상 OS: macOS 또는 Windows. Windows system/hotkey 설정 변경은 Windows 필수

1. 언어, key pressed time, loop delay를 변경하고 재실행 후 복원되는지 확인한다. 초기화는 기본값을 보여주되 확인 전에는 저장하지 않아야 한다.
2. 수정키 세트를 선택하고 ⚙ 메뉴에서 편집·복사·삭제한 뒤 시작 시 해당 세트가 실제 키 입력에 반영되는지 확인한다.
3. 보조 창(작업 공간·캡처 HUD·설정) 위치를 변경하고 다시 열었을 때 화면 밖으로 벗어나지 않는지 확인한다.
4. 재시작 후 실행 창의 대상·실행(프로필 또는 실행 세트)·수정키 선택이 복원되는지 확인한다. 예전 버전의 `app_state.json`(실행 세트 `__current__`)도 프로필 선택으로 열려야 한다.
